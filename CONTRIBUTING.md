# Contributing

This repository is a controlled experiment, so changes must preserve the distinction
between scientific evidence and presentation.

## Development setup

Use native CPython 3.13.15 on Apple Silicon:

```bash
./setup_venv.sh
```

Run the local quality gates before proposing a change:

```bash
.venv/bin/python -m pytest -q -p no:cacheprovider
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
.venv/bin/python -m mypy src
.venv/bin/python scripts/check_repository.py
```

## Experiment changes

- Change valid experiment parameters in `configs/experiment.yaml`, not by adding matching
  constants to Python code.
- Treat a configuration change as a new experiment identity. Never relabel old checkpoints or
  numerical outputs as belonging to the new configuration.
- Preserve the official test partition, calibration isolation, attack bounds, paired sample
  alignment, and fixed-checkpoint rule.
- Add or update tests for attacks, model state, metrics, calibration, representations, and
  provenance before making a new scientific claim.
- Keep observations, interpretations, and speculation separate.

## Result and notebook changes

The guided notebook is generated by `scripts/build_notebook.py` and must remain output-free with
`RUN_FULL_EXPERIMENT = False`. The visual result notebook and public aggregate are presentation
artifacts built from completed, hash-matched evidence:

```bash
.venv/bin/python scripts/build_public_results.py
.venv/bin/python scripts/build_results_notebook.py --force
```

These commands do not train or run attacks. Do not hand-edit reported numbers. Raw photographs,
weights, checkpoints, logits, features, per-sample arrays, and local manifests must remain ignored.

## Claim boundary

The recorded result concerns one ResNet-18 pair, one split and seed family, and a finite bounded
digital attack. Contributions must not describe it as certified, physical, generally robust, safe,
or production-ready.
